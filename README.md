# Family

Версия приложения: 1.2.0.

Локальное приложение совместных финансов для Тимура и Беллы. Добавляйте свои категории, общие и личные счета и операции; автор операции выбирается отдельно от счёта. На главной панели виден свободный остаток после резервов целей и наступивших неоплаченных обязательств. Данные сохраняются на этом компьютере между неделями и перезапусками. Банковские интеграции не подключены.

## Требования

- Node.js 20.9 или новее
- pnpm 10 или новее

## Запуск веб-версии

cd "$env:USERPROFILE\Desktop\Баланс"
pnpm install
pnpm dev

Откройте http://localhost:3000. Проверки: pnpm lint, pnpm test. Для обычной серверной сборки: pnpm build.

## Отдельное приложение Windows

Для разработки: pnpm desktop:run

Для создания переносимого EXE: pnpm desktop:dist

Готовый файл появится в release\Family-1.2.0.exe. Запуск не требует Edge или локального сервера. В меню «Обучение» есть пошаговая подсказка по созданию категорий, счетов и операций.

В Windows EXE данные хранятся локально в профиле пользователя и защищены системным шифрованием Windows. После успешного сохранения предыдущая версия файла остаётся как резервная копия .bak; при повреждении основной версии приложение попробует восстановить последнюю копию. В веб-режиме разработки данные хранятся локально в браузере.

В версии 1.2.0 в разделе «Обучение» доступна кнопка «Скачать отчёт для ChatGPT». Она создаёт один Markdown-файл со сводкой, помесячными итогами, бюджетами, целями и историей операций. Имена участников и счетов заменяются условными обозначениями; описания операций и названия категорий, целей и регулярных платежей сохраняются, поэтому перед отправкой проверьте файл на личные сведения.

Если сборка portable EXE не завершилась, ярлык может вести на `Family.exe` в папке `release-<версия>-app\win-unpacked`. Для работы приложения оставляйте эту папку целиком на месте.

Локальное хранилище не синхронизируется между компьютерами или Windows-профилями. Supabase Auth и общий облачный доступ для Тимура и Беллы пока не подключены — для этого понадобится отдельный этап с настройкой Supabase и миграциями.

## Переменные окружения

Для будущей авторизации и базы данных скопируйте .env.example в .env.local и задайте NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_ANON_KEY. Секретный service_role нельзя передавать клиенту. Сейчас авторизация Supabase ещё не подключена.

## Модель данных

Суммы хранятся в целых копейках, валюта пространства закреплена как RUB. У операции отдельно хранятся автор записи и счёт; автор выбирается в верхней панели, он не зависит от владельца счёта. Старые записи без автора показываются как «Не указано». Перевод связывает исходный и целевой счёт; его сумма не включается в доходы и расходы. Взнос в цель не создаёт новую сумму на счетах. Даты операции и создания записи независимы.

## Резервная копия и восстановление

Откройте раздел «Обучение» и выберите создание или восстановление копии. Экспортированный файл содержит всю базу Family и защищён паролем с помощью AES-256-GCM. Пароль не хранится в приложении; без него открыть копию нельзя. Восстановление заменяет текущие данные, предварительно сохраняя их в локальной резервной копии. Для переноса используйте файл копии и заданный при экспорте пароль.

## Текущая версия

- src/app/page.tsx — адаптивная панель, обучение, операции, бюджеты, цели с журналом резервов, ручное подтверждение регулярных платежей и аналитика за 6 месяцев.
- src/lib/family-data.ts — суммы в копейках, балансы счетов, цели без двойного учёта денег, календарь регулярных платежей и расчёты аналитики.
- src/lib/family-backup.ts — переносимая резервная копия с парольным шифрованием.
- desktop/storage.cjs — локальное зашифрованное хранение и восстановление копии для EXE.
- supabase/migrations/ — схема и политики RLS для будущего облачного этапа.
- tests/ — финансовые расчёты, бюджетирование, накопления, даты платежей, аналитика, хранилище и шифрование резервной копии.

В версии 1.2.0 активированы цели, регулярные платежи и аналитика; подтверждение регулярного платежа одновременно записывает расход и переносит срок без двойного вычета из свободного остатка. Автор операции сохраняется отдельно от владельца счёта, а старые записи остаются без ложной атрибуции. Облачная авторизация, совместная синхронизация и банковские интеграции по-прежнему не подключены.

## Выпуск новой версии

Для выпуска одним действием используйте `pnpm release:major` (крупное: увеличивается первое число), `pnpm release:minor` (среднее: второе) или `pnpm release:patch` (hotfix: третье). Например, из `1.0.6` получится `2.0.0`, `1.1.0` или `1.0.7`. Команда повышает номер, синхронизирует его в приложении и README, собирает `Family-<версия>.exe` и обновляет ярлык рабочего стола. Только изменить номер без сборки можно командами `pnpm version:major`, `pnpm version:minor` или `pnpm version:patch`. Предпросмотр без записи: `pnpm version:minor -- --dry-run`.
